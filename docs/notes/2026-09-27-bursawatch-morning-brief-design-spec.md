### Daily rotation windows for several-day swing context

The user would accept a 20-trading-day relative-strength window with a five-day momentum window if it is a good fit for trades held several days, but did not independently select or validate those parameters. The [RRG creator's explanation](https://articles.stockcharts.com/article/articles-rrg-2016-10-addressing-rrg-feedback-and-questions-from-chartcon-2016/) recommends daily observations for swing trading and says there is no universal numerical momentum/strength pair; it also cautions that RRG is a context tool rather than a trade guarantee. The user then chose the faster 10/3-day candidate as the first-version design preference. It may react sooner but may also be noisier; do not describe it as a proven optimum. Compare it with 20/5 on actual IDX sector and conglomerate histories before final production calibration, checking response time, quadrant flipping, and how often a new quadrant persists for the intended several-day holding horizon. This is design evaluation, not an instruction to generate trading signals or to implement now. The user subsequently approved the independently defined formula below, inspired by the visual reference rather than a reproduction of proprietary RRG internals.

The confirmed independent formula uses daily basket returns from the same eligible member set and fixed dated percentage weights. Compound those daily returns over the latest ten trading sessions to obtain the basket return `R_b,10(t)`; obtain `R_i,10(t)` from IHSG over the same sessions. The horizontal coordinate is `X(t) = 100 × [R_b,10(t) - R_i,10(t)]` percentage points. The vertical coordinate is `Y(t) = X(t) - X(t-3)` percentage points. `X > 0, Y > 0` is Leading; `X < 0, Y > 0` Improving; `X > 0, Y < 0` Weakening; `X < 0, Y < 0` Lagging. Exact zero sits on a neutral axis and is not assigned a quadrant. A basket can lead IHSG while its absolute return is negative. The five displayed daily positions need older observations to initialize the ten-session windows and three-session changes; do not draw a full trail from insufficient history.

Three bootstrap approaches are distinct design options:

- **Fixed snapshot weights applied to older returns:** use the same dated market-cap percentages at every historical point. This is a historical illustration using later information, with constant percentage allocations effectively rebalanced each day. A suitable label is "Historical illustration using fixed [date] market-cap weights."
- **Current share quantities applied backward:** derive quantities from compatible snapshot cap and price, then let weights drift over the historical prices. This assumes those quantities and the snapshot membership existed earlier; issuance, buybacks, splits, and membership changes need compatible treatment. It is a different historical approximation, not a repair of missing historical weights.
- **A portfolio initialized at the snapshot date:** apply known weights prospectively and let holdings drift between maintenance boundaries. This provides a prospective series; earlier rotation trails still require separately sourced dated weights or a labeled approximation.

These distinctions are design deductions supported by the separation of prices, quantities, and index maintenance in [S&P's index mathematics methodology](https://www.spglobal.com/spdji/en/documents/methodologies/methodology-index-math.pdf). Refreshing to actual prevailing caps is different from restoring constant snapshot percentages. With unchanged share quantities and membership, cap-weighted holdings can drift with prices without trading solely to follow price changes. Neither total-cap approach reproduces an official float-adjusted IDX index.
